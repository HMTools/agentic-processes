## Pre-Implementation: Verify Existing Patterns ✅

Before creating new components, check if similar implementations exist to maintain consistency and avoid duplication:

### Existing Components
- [ ] Search for similar components in relevant directories
- [ ] Review naming conventions and patterns
- [ ] Check existing component structure and method signatures
- [ ] Note common dependencies and patterns

### Contracts/Models
- [ ] Search for similar contract models or DTOs
- [ ] Review existing contract patterns (nullable types, required fields, validation attributes)
- [ ] Note naming conventions for models
- [ ] Check immutability patterns (`init` properties, `required` modifier)

### Patterns and Conventions
- [ ] Review how existing components handle similar operations
- [ ] Check error handling approaches
- [ ] Identify common validation patterns
- [ ] Note logging patterns
- [ ] Review async/await usage in similar scenarios

### Integration Patterns
- [ ] Check how existing components interact with dependencies
- [ ] Review patterns for external service calls (if applicable)
- [ ] Note transaction management patterns (if applicable)
- [ ] Check event publishing/subscription patterns (if applicable)
- [ ] Review data mapping approaches

### Configuration & Settings
- [ ] Review existing configuration patterns
- [ ] Check configuration file structure and organization
- [ ] Verify DI registration patterns
- [ ] Note common configuration properties
- [ ] **Review**: [Configuration vs Constants Guide](../../../../knowledge/best-practices/implementation-templates/configuration-vs-constants.md) - Determine when to use Settings classes vs constants

### Built-in Helpers
- [ ] Search for existing utility methods that might solve the problem
- [ ] Check for built-in framework features
- [ ] Review extension methods that might simplify implementation
- [ ] Note reusable helper classes

### Documentation
- [ ] Document discovered patterns in process memory file
- [ ] Note similar components as reference examples
- [ ] Record any deviations from standard patterns with rationale
- [ ] List reusable utilities/helpers found
